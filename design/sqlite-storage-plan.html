SQLite 存储层重设计 — 调研报告与实施计划

以插件私有的 node:sqlite 数据库作为唯一派生存储：会话级 / 步骤级行式建模，版本不符即全量重建，查询即 SQL， 前端只拉取细粒度 API。现有投影注册、JSON 缓存、内存聚合与粗粒度路由全部打破重做；折叠引擎与全部 dsh 原生数据接缝保留。

依据：dsh master (0.2.2-rc.3) 与 dsh-context 0.84.1 源码逐行调研；所有论断附文件:行号证据。

需求设计落点要点

10重建/删除可行性§4.3 生命周期任何会话行集都可由持久日志确定性重建（折叠是纯函数）；删除走外键 CASCADE；会话消失 / 日志改写 / 版本升级 / 完整性损坏均给出明确触发与动作。
11索引设计§6 索引设计每条索引对应到具体查询模式（日聚合 / 名目 tally / 家族树 / 游标分页 / 存量过滤），不做无主索引。

2.3 折叠引擎产出的全部数据形态（新表设计的直接输入）

事件 → 派生事实（每条都应成为一行）

  • assistant/message → LLM 调用行：当时上下文构成（system/tools/user/inject/skill/assistant/tool/total）、usage 四桶、turn/step、TTFT 与 gen 时窗。
  • step/start→step/end → 步骤行：wall/active/wait/idle/tool-busy、首 token 时刻、节拍封顶标记（fold.ts:585-655）。
  • tool/call→tool/result 及 PTC 对 → 工具调用行：名称、起止、时长、错误、shell 命令文本（≤4096）、退出码、程序名归组（fold.ts:400-575）。
  • 表面节点（user/inject/skill/assistant/tool）→ 表面行：类别、tokens、reasoning/answer/call 拆分、imgs、工具名、预览；compaction/prune/system 替换 → gone_seq 归档标记（fold.ts:169-289）。
  • compaction/prune/inject/model/mode → 事件行（fold.ts:683-970）。
  • request/header → 头纪元行 + 逐工具 schema 估值行（headers.ts:65-108）。
  • system/message → 系统提示行（被替换的旧提示从状态删除，fold.ts:369-385）。
  • file ops（read/write/search）→ 文件操作行（fold.ts:743-801；shared/fileOps.ts）。
  • 技能装载三条路径（invocation / result / PTC dispatch）→ 技能装载行（activity.ts:199-321）。
  • 计时 span（ttft/reasoning/text/toolarg/tools/other）→ span 行（fold.ts:618-640）。

折叠态维护的标量（终稿口径，评审修订）

  • 回写 sessions 的仅两把排序键：billed_tokens / cur_total（flush 时按行集现算回写）+ 最新态 model / provider / reasoningEffort / contextWindow / maxOutputTokens / last_user。
  • 运行计数（turns/steps/injects/…）与计时总量（wall/ttft/gen/…）折叠器不再驻留 —— 全部由子表派生（§5.2 派生对照）。

不入库（服务时计算 / 直读 dsh）

  • 成本 = usage 行 × 价目表（host 已持有，1h TTL）；faces/misses 由 DISTINCT(provider,model) 现算。
  • running / archived / 分组 = workspaceRegistry / agents 镜像列（带刷新触发）。
  • 标题 = dsh title 投影；消息正文、工具输出、fleet 消息 = 按需 RPC 读原始日志。

3.2 核心决策

编号决策理由与代价
D1SQLite 为唯一派生存储同时取代投影注册+session_projcache 行、overview JSON 缓存、请求期内存 feed、detail/delta/facts 冷缓存。消除「同一派生数据存 4 处」的根本冗余；查询/聚合/分页成为索引扫描而非 JS 遍历。
代价：折叠器必须自行管理活会话折叠与冷回填（两者皆有已验证的实现模式可复用）。
D2折叠引擎保留为纯计算，改造成「行发射器」applyTimeline/applyActivity 的计量口径（token 估值、峰谷分桶、idle 刻雕、TTFT 锚点）经过 diff-fold 差分校准，全部保留；改变的是终点——状态不再攒成大对象，而是在终结点(步骤结束/工具结算/请求落定)发射为行。
D3事件来源与接缝全部沿用现状session/event 推送、observeSession('none')、stat/open/read(offset)、connection.fetch.register、heap 冷读门、切片/worker 折叠、回填节流——每一项都是当前代码已在三个支持线上运行的接缝，兼容风险最小。
D4聚合策略两分法多行事实的横切统计（按日、按名目、按模型、按路径）→ 一律 SQL GROUP BY 现算，废除 activity-days 账本与全部 tally 上限；sessions 仅保留 billed_tokens / cur_total 两把排序与热路径键（flush 时按行集现算回写，幂等），其余计数/计时全部派生（需求 4：能查表就不预聚合）——折叠态随之瘦身：timing/totals/turnRuns/cost 不再驻留折叠器。
D5原始文本零入库，成本零入库消息正文/工具输出/system prompt 内容/fleet 消息不进库（仅 ≤2,000 字符展示预览——渲染必需截断，全文仍走 history RPC，评审修订）；全文检索复用 dsh sessionQuery FTS（可选启用）；成本=usage 行×价目表服务时计算，价目更新无需任何数据迁移。

④ 版本与重建策略

4.1 数据库身份与版本门禁

-- 打开序列（与 dsh session-query-sqlite / storage-sqlite 同款惯例）
PRAGMA application_id  = 0x44534358;   -- 'DSCX'，区别于 dsh 的 'DSHQ'(0x44534851)
PRAGMA user_version    = 8;            -- DSHCTX_SCHEMA_VERSION（整数，无迁移语义）
PRAGMA journal_mode    = WAL;
PRAGMA foreign_keys    = ON;
PRAGMA busy_timeout    = 5000;
PRAGMA synchronous     = NORMAL;       -- 派生可重建数据，WAL+NORMAL 足够
PRAGMA cache_size      = -8000;        -- 8 MB 页缓存上限
打开时检查动作
application_id 非 0 且 ≠ 'DSCX'拒绝打开（他方数据库，永不触碰）——同 dsh session-query-sqlite/schema.ts:58-63。
user_version ≠ SCHEMA_VERSION（含 0 但已有表）删除全部用户表 → 重置 user_version=0 → 重建 schema → 重播种 meta。数据全部来自可重放的持久日志，重建安全（需求 2 的「任何不同即完全重建」）。同款先例：session-query-sqlite/schema.ts:64-101 resetDerivedSchema。
空库（application_id=0 且无表）建 schema、写 application_id + user_version。
PRAGMA quick_check 失败 / 打开异常删文件重建；仍失败 → 尝试 :memory: 降级（全功能、随进程消失）+ warn 日志；两者皆败 → 路由统一 ready:false，前端渲染重试提示，宿主进程不受影响。
检测到旧 overview-cache.v1.json首次成功建库后删除（一次性清理，失败静默）。

4.2 SCHEMA_VERSION 的 bump 规则

  • 任何表结构 / 字段语义 / 口径变化都必须 bump —— 因为不迁移：旧行口径与新查询混杂即是数据错误（符合编码标准「数据准确性第一」）。
  • 派生数据完全可重建，bump 的代价仅是首次启动的回填时长（有节流与 worker，不阻塞使用；未回填会话按 §8 的 coverage 显示 «—»）。
  • 与 fold_state 的状态载荷格式变化共用同一版本号：载荷不兼容时该表整体清空（等价于回退到全量重折叠）。

5.0 命名与冗余约定（先立规矩，再列字段）

命名约定（需求 7）

  • snake_case；主键列名全库一致：session_id、seq（源事件序号）。
  • *_seq = 引用其他事件的序号（result_seq / parent_seq / request_seq / gone_seq / epoch_seq / span_seq）。
  • *_tokens / *_ms = 计量；*_at = 生命周期时间戳（created_at / updated_at / folded_at）；事件时间统一叫 time（配对事件用 start_time / end_time）。
  • day = 折叠时用 dayKeyOf() 算好的本地日键（'YYYY-MM-DD'）——日聚合一律走它，SQL 内不做时区运算。
  • 布尔 INTEGER 0/1；枚举 TEXT + CHECK；金额永不入库。
  • 避让 SQL 关键字：模型变更用 model_from/model_to（不用 from/to）。

冗余判定五规则（需求 4/8）

  1. 原文不复制：消息正文、工具输出、system prompt 文本、fleet 消息不入库；展示需要处只留 ≤2,000 字符 preview（渲染必需的截断预览，全文按需走 RPC，§5.6）。
  2. 折叠态只落排序键：sessions 仅保留 billed_tokens / cur_total 两把排序与热路径键（flush 时按行集现算回写，幂等）；其余计数/计时一律子表 GROUP BY 现算 —— 禁止为查询新造预聚合（days/tallies 全废，会话级计数列亦裁剪），并消灭「计数器 = 子表 SUM」的双源不变量。
  3. 可由行集 GROUP BY 现算的 → 不设列：当前构成分类拆分（surface_nodes 求和）、成本（usage×价目）、名目统计、文件聚合全部现算；仅保留排序键（billed_tokens、cur_total）与列表显示所需最小列。
  4. dsh 服务在请求时零成本可得的 → 镜像列 + 明确刷新触发：archived/workspace_title/running/title/blank（刷新触发见 §8.5），字段语义以 dsh 为准。
  5. 派生但查询高频且纯函数的 → 折叠时算好存列：day、period（峰/谷）、starts_turn、program、plugin 归属——存一次，省去查询端 JS 重算。

8.1 Boot 对账（启动即主动回填，活跃优先）

      coldReads.admit(堆门, FIFO)                      ← 沿用现状（coldRead.ts）
